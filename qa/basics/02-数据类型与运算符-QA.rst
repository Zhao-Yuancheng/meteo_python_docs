.. _21-引号标点与括号代码没对上号的-syntaxerror:

2.1 引号、标点与括号：代码“没对上号”的 SyntaxError
--------------------------------------------------

   这类错误是\ **词法/语法层面**\ 的：程序根本没跑起来，\ ``SyntaxError``\ （语法错误）在“读代码”阶段就被判了死刑。它们占大一新生报错的一大半。核心记忆：\ **代码只能认得英文半角符号**\ （\ ``，（）；``
   这种全角中文符号一概不认），以及\ **引号、括号必须成双配对**\ 。

--------------

.. _211-引号不闭合单双三引号-syntaxerror:

2.1.1 引号不闭合（单/双/三引号）→ ``SyntaxError``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

单引号未闭合（\ ``s = '兰州今天有雷暴``\ ）：

.. code:: text

     File "...\sim\ch02\e01_single_quote_unclosed.py", line 3
       s = '兰州今天有雷暴
           ^
   SyntaxError: unterminated string literal (detected at line 3)

双引号未闭合（\ ``s = "本站气压 848.6 hPa``\ ）：

.. code:: text

     File "...\e02_double_quote_unclosed.py", line 3
       s = "本站气压 848.6 hPa
           ^
   SyntaxError: unterminated string literal (detected at line 3)

三引号（多行字符串）未闭合（\ ``doc = """`` 开了头没封口）：

.. code:: text

     File "...\e03_triple_quote_unclosed.py", line 3
       doc = """
             ^
   SyntaxError: unterminated triple-quoted string literal (detected at line 5)

**重要版本差异**\ ：上面是 **3.12**
的真实输出，报错已经很“贴心”。在较老的
Python（3.6–3.9）里，这类情况统称报：

.. code:: text

   SyntaxError: unexpected EOF while parsing

``EOF`` 是 End Of File（文件末尾），\ ``unexpected EOF while parsing``
直译“解析中意外地撞到文件结尾”——意思就是：\ **该闭合的东西没闭合，Python
从头读到文件最后一格都没等到那个收尾引号/括号**\ 。通用方法论 0.6
节那张“关键词→联想”表里，就把 ``unexpected EOF while parsing``
对应到“引号或括号没闭合，到下个空行才报”。\ **在本环境实践中，看懂上面三种
``unterminated ...`` 即可，见到 ``unexpected EOF`` 时能对上号就行。**

**关于“整条字符串沿打印到空行才报错”的现象**\ ：当引号没闭合时，Python
会把\ **后面所有没引号的内容全当作这个字符串的一部分**\ （这叫“字符串吞掉后续行”）。所以错误往往报在“应合而未合”处，甚至报在很靠后的空行。上表
``e03`` 报在 “detected at line 5”（最后一行），就是因为 ``"""``
一路吞到脚本末尾才撞上
EOF。\ **定位口诀**\ ：报错行不是你真正出错的逻辑，往上找字符串的开头引号，大概率就是漏了收尾。

**原因**\ ：字符串字面量需要一个成对的引号包裹。开了一个引号却没在合理的地方闭合，解析器一路往后吃，直到文件结尾，于是抛错。

**解决办法**\ （补上收尾引号）

.. code:: python

   s = '兰州今天有雷暴'            # 单引号闭合
   s2 = "本站气压 848.6 hPa"      # 双引号闭合
   doc = """                      # 三引号闭合成对
   兰州站天气实况：
   午后有较强对流云团发展。
   """
   print(s, s2); print(doc)

..

   **气象场景一句话**\ ：就像一份电报发了“今天有雷阵雨”却没写收尾的站点名和发报时次，报文处理程序读到文件末尾都拼不完整一行记录，干脆拒收整份报文——补全闭合，报文才能“着落”。

.. _212-括号花括号不闭合---was-never-closed--unexpected-eof-while-parsing:

2.1.2 括号/花括号不闭合 → ``'(' was never closed`` / ``unexpected EOF while parsing``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

圆括号未闭合（\ ``x = (1 + 2``\ ）：

.. code:: text

     File "...\e00_unclosed_paren.py", line 3
       x = (1 + 2
           ^
   SyntaxError: '(' was never closed

花括号/字典未闭合（\ ``d = {'a': 1, 'b': 2``\ ）：

.. code:: text

     File "...\e00b_unclosed_brace.py", line 3
       d = {'a': 1, 'b': 2
           ^
   SyntaxError: '{' was never closed

（老版本统一报 ``SyntaxError: unexpected EOF while parsing``\ 。）

**原因**\ ：\ ``(`` ``)``\ 、\ ``[`` ``]``\ 、\ ``{``
``}``\ 、引号——这些符号 Python
要求“成对出现”。漏掉右半边，解析器就满怀期待地读到文件末尾，却在结尾撞上“意外结束”。报错信息清晰地告诉你是哪一个符号
“``'(' was never closed``”（\ ``(`` 没被闭合）。

**解决办法**\ ：补上对应的右括号/右花括号。日常小技巧：\ **先写闭合再填内容**\ ，或写完用
``Ctrl+[空格]``/格式化工具（如 VSCode 的 Prettier）自动配对检查。

.. code:: python

   x = (1 + 2) * 3
   d = {'a': 1, 'b': 2}
   print(x, d)

..

   **气象场景一句话**\ ：括号没配对就像探空气球本该绑“一个升空一个回收”的成对平衡器，结果只放飞了(a
   没合上)，整个回执数据流到地就断档，观测站只能干等。

.. _213-中文标点混入--syntaxerror-invalid-character--uff0c:

2.1.3 中文标点混入 → ``SyntaxError: invalid character '，' (U+FF0C)``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

中文逗号出现在 ``print`` 参数分隔处：

.. code:: text

     File "...\e04_chinese_comma.py", line 3
       print("气温", 35.6， "湿度", 45)
                       ^
   SyntaxError: invalid character '，' (U+FF0C)

中文逗号出现在列表元素分隔处：

.. code:: text

       stations = ['兰州'，'敦煌'，'西宁']
                       ^
   SyntaxError: invalid character '，' (U+FF0C)

中文（全角）圆括号当作函数调用括号：

.. code:: text

       print（"高温预警"）
            ^
   SyntaxError: invalid character '（' (U+FF08)

中文（全角）分号当作语句分隔：

.. code:: text

       temp = 35.6；湿度 = 45
                  ^
   SyntaxError: invalid character '；' (U+FF1B)

..

   同类还有：中文引号 ``“ ”``\ 、全角冒号 ``：``\ 、全角句号
   ``。``\ 。报错里都有一个括号，里面是 **``U+FFxx`` 这样一个 Unicode
   码点**——那是全角符号的身份证号（\ ``U+FF0C``\ =中文逗号、\ ``U+FF08``\ =中文左括号、\ ``U+FF1B``\ =中文分号）。看到
   “``invalid character`` + U+FFFF”
   就立刻知道：\ **代码里混进中文字体输入的标点了**\ 。若非法字符更隐蔽（如复制网页代码带进来的特殊空白），会报
   ``invalid non-printable character``\ 。

**原因**\ ：Python（和其它大多数语言）只认\ **英文半角**\ 的
``, ( ) ; :``
等符号。你在中文输入法状态下按的是“中文逗号”，它长得和英文逗号几乎一样，但字节完全不同，Python
不认账。注意：\ **字符串内部**\ 用中文没事（\ ``"兰州，晴"``
合法），出错的都是\ **字符串外层**\ 那些作为语法符号的标点。

**解决办法**\ ：把报错行所有中文标点改回英文半角。切换到\ **英文输入法**\ 再写代码；若是从
Word/网页复制来的代码，先粘贴成\ **纯文本**\ ，再用编辑器的“替换”把全角
``，`` 换成半角 ``,``\ 。

.. code:: python

   print("气温", 35.6, "湿度", 45)
   stations = ['兰州', '敦煌', '西宁']
   print("高温预警")
   temp = 35.6
   humidity = 45

..

   **气象场景一句话**\ ：英文代码把中文逗号当分隔符，就像地面填报表本该用半角逗号切分要素列，却混进一个全角逗号，整行
   CSV 的列数对不上，读数的程序当场翻脸。

.. _214-字符串内部还要引号--引号嵌套错误-invalid-syntax:

2.1.4 字符串内部还要引号 → 引号嵌套错误 ``invalid syntax``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

想在双引号字符串里再放一个双引号（“兰州真热”），直接写成外层内层都用双引号：

.. code:: text

     File "...\e07_quote_nesting_bad.py", line 3
       s = "他说"兰州真热""
               ^^^^
   SyntaxError: invalid syntax

**原因**\ ：\ ``s = "他说"``
其实是一个完整字符串（内容是“他说”），后面的 ``兰州真热``
就成了“裸奔”的非法文字，Python 不知道它是什么，于是
``invalid syntax``\ 。本质是\ **引号撞车**\ ：内外的引号同一型号，解析器分不清哪一对包谁。

**解决办法**\ ：三种正确做法，任选其一，含义完全相同：

.. code:: python

   # 做法1：外单内双   —— 最直观，推荐默认
   a = '他说"兰州真热"'

   # 做法2：外双内单
   b = "他说'兰州真热'"

   # 做法3：转义符 \"   —— 外层引号前加反斜杠，让"成为普通字符
   c = "他说\"兰州真热\""

   # 做法4：三引号（万一内层单双都要出现）
   d = '''他说"兰州真热"'''

   print(a); print(b); print(c); print(d)

运行输出（e07b 实测）：

.. code:: text

   他说"兰州真热"
   他说'兰州真热'
   他说"兰州真热"
   他说"兰州真热"

..

   **气象场景一句话**\ ：就像在警报文案里要加引号（“暴雨红色预警信号”），标题本身又带引号，你得用“单引号套双引号”或转义，别让引号互相“抢地盘”。

--------------------------------------------------

.. _221-数字和字符串混着算--typeerror-unsupported-operand-types-for--int-and-str:

2.2.1 数字和字符串混着算 → ``TypeError: unsupported operand type(s) for +: 'int' and 'str'``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

整数 + 字符串：

.. code:: text

     File "...\e08_int_add_str.py", line 3, in <module>
       print(25 + "5")
             ~~~^~~~~
   TypeError: unsupported operand type(s) for +: 'int' and 'str'

带引号的数字 + 整数（\ ``'5' + 9``\ ）：

.. code:: text

     File "...\e09_str_add_int.py", line 3, in <module>
       print('5' + 9)
             ~~~~^~~
   TypeError: can only concatenate str (not "int") to str

**原因**\ ：\ ``+`` 对 ``int`` 是做加法，对 ``str`` 是拼接。Python
**拒绝猜测**\ 你到底是想要导数值还是合并文本，于是直接报
``TypeError``\ （类型错误）——``unsupported operand type(s)``
意思是“这两类操作数不支持 ``+`` 这个运算”。第二种报错
``can only concatenate str (not "int") to str`` 是 Python 3.9+
的细化提示：“字符串只能拼接字符串”，同样一个性质。

**解决办法**\ ：先想清楚要哪种结果。

- 想要\ **数值相加** → 把字符串转数字 ``int("5") + 25``\ ；
- 想要\ **文本拼接** → 把数字转字符串
  ``str(25) + "5"``\ ，或\ **更推荐用 f-string**\ 。

.. code:: python

   print(int("5") + 25)        # 30：转数字再加
   print(str(25) + "5")        # 255：转字符串拼接
   print(f"{25}5")             # 255：f-string 拼接，最省心

对应正文 ``datatypes.rst`` 的警示：“``"25"`` 是文本，\ ``"25" + 5``
直接抛 TypeError，须先转换 ``int("25") + 5``\ 。”

   **气象场景一句话**\ ：就像把湿度 ``65%`` 的“百分比文本”混进数值列表去
   ``sum``\ ，或把整站气温 ``35`` 和站名 ``"兰州"`` 硬加——Python
   不背这个锅。排查方向：先 ``print(type(...))``
   确认两边到底是不是同一类。

.. _222-除以-0--zerodivisionerror整数浮点取模整除:

2.2.2 除以 0 → ``ZeroDivisionError``\ （整数/浮点/取模/整除）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

整数除以 0：

.. code:: text

     File "...\e17_division_by_zero.py", line 3, in <module>
       print(10 / 0)
             ~~~^~~
   ZeroDivisionError: division by zero

浮点数除以 ``0.0``\ （除数写成了 0.0，同样是 0）：

.. code:: text

     File "...\e17b_div_by_zero_float.py", line 3, in <module>
       print(10 / 0.0)
             ~~~^~~~~
   ZeroDivisionError: float division by zero

取模（余数）除以 0：

.. code:: text

     File "...\e17c_mod_zero.py", line 3, in <module>
       print(10 % 0)
             ~~~^~~
   ZeroDivisionError: integer modulo by zero

**原因**\ ：\ ``0`` 和 ``0.0``
都是零，任何数除以零在数学上无定义。\ ``/``\ 、\ ``//``\ 、\ ``%``
这三种“除”都会触发 ``ZeroDivisionError``\ （属于 ``ArithmeticError``
家族）。注意报错文案也有细微差别：整行为
``division by zero``\ ，浮点行为 ``float division by zero``\ ，取模为
``integer modulo by zero``——**关键词 ``ZeroDivisionError``
就是主菜**\ 。

**解决办法**\ ：除数先判零再算，或对除数来源做好校验。

.. code:: python

   divisor = 0
   if divisor != 0:
       print(10 / divisor)
   else:
       print("除数为 0，跳过（这是缺测/空数据常客）")

气象里的典型雷区：\ **求平均风速时 ``sum / len``
而列表为空**\ ，或某天降水缺测填了 0 当除数。空/零源都会炸
``ZeroDivisionError``\ ，处理数据前先 ``len()`` 和判零。

   **气象场景一句话**\ ：除以 0 就像算“日变率”时用“平均间隔 0
   天”当分母——观测日期没拉开、甚至重复给了同一天，变率就变得无穷大，必须检查分母是否非零。

.. _223-浮点精度01--02--03不报错但结果错:

2.2.3 浮点精度：\ ``0.1 + 0.2 != 0.3``\ （不报错，但结果错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e18 实测，注意是\ **无报错但结果不对**\ ）

.. code:: text

   0.30000000000000004
   False
   True
   True

展开：\ ``print(0.1 + 0.2)`` 出的是 ``0.30000000000000004``\ ，于是
``0.1 + 0.2 == 0.3`` 是 ``False``\ ；改成容差比较
``abs((0.1+0.2)-0.3) < 1e-9`` 得
``True``\ ，\ ``round(...) == round(...)`` 也得 ``True``\ 。

**原因**\ ：浮点数按 **IEEE 754
标准**\ 用二进制存储，\ ``0.1``\ 、\ ``0.3``
这样的十进制小数无法被二进制\ **精确**\ 表示，只能存成“最接近的值”。两个近似值一加，误差攒到第
16 位之后，\ ``==``
就判不相等了。\ **程序百分百“正常”跑完，却也百分之百“算错了”**——正是通用方法论
0.1 节说的最阴险的“异常现象（无报错）”。

**解决办法**\ ：

- **判等用容差**\ ：\ ``abs(a - b) < 1e-9``\ （正文推荐）；
- **先四舍五入再比**\ ：\ ``round(0.1+0.2, 10) == round(0.3, 10)``\ ；
- **必须出报告值**\ （观测建档、经费核算）用标准库
  ``Decimal``\ ，用\ **字符串**\ 构造：

.. code:: python

   from decimal import Decimal, getcontext
   getcontext().prec = 5
   x, y = Decimal("0.1"), Decimal("0.2")
   print(x + y)                                  # 0.3  精确
   print(x + y == Decimal("0.3"))                # True

..

   正文 ``datatypes.rst`` 特别提醒：气象上“判断两个温度相等”别直接用
   ``==``\ ；对科学计算保留 ``float`` 就够，10⁻¹⁷
   量级误差远小于观测精度，\ ``Decimal`` 知道有这回事即可。

   **气象场景一句话**\ ：0.1
   这种小数在“二进制观测台”上永远差那么一万亿分之一克，就像一张电子温度记录，第
   16 位小数总有几个“假抖动”；同款两次取样判“相等”就会翻车，得给“相等”留
   0.000001 的容差尺。

.. _224--不是幂是异或不报错但算出来全错:

2.2.4 ``^`` 不是幂：是异或（不报错，但算出来全错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e21 实测）

.. code:: text

   8
   1
   9
   1

即：\ ``2 ** 3`` 得 ``8``\ （正确的幂）；\ ``2 ^ 3`` 得
``1``——**不报错**\ ，但 \`2^3=2³=8\`
的直觉在这里是\ ``1``\ ！\ ``3 ** 2`` 得 ``9``\ ，\ ``3 ^ 2`` 也得
``1``\ 。

**原因**\ ：学过 C/数学符号的你惯性认为 ``^`` 是“几次方”，但 Python 里
``^`` 是\ **按位异或（XOR）**\ （对着二进制逐位比，相同得 0、不同得
1），其优先级还很低。\ **幂运算只有一个符号：\ ``**``**\ 。这是想当然埋下的“静默污染”——程序不报错，结果却离谱。

**解决办法**\ ：一律用 ``**`` 表幂。

.. code:: python

   print(2 ** 3)     # 8
   print(3 ** 2)     # 9
   # 风速合成：u² + v² 再开方
   u, v = 3.0, 4.0
   print((u**2 + v**2) ** 0.5)   # 5.0

..

   可顺带记住 Python 的位运算符
   ``&``\ （与）\ ``|``\ （或）\ ``^``\ （亦或）在\ **集合**\ 上还有特殊含义：对
   ``set``\ ，\ ``&`` 是交集、\ ``|`` 是并集、\ ``^``
   是对称差（正文集合一节）。对象不同含义不同——**算子号前先看操作数是数还是集合**\ 。

   **气象场景一句话**\ ：想算“风速平方”却用了
   ``^``\ ，等于把风矢量按位异或了一把，画出来风场全是乱的——这是“不报错但全错”的典型，发现异常先查运算符对不对。

.. _225-运算符优先级3--2--2-与-3--2--2:

2.2.5 运算符优先级：\ ``3 + 2 * 2`` 与 ``(3 + 2) * 2``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ （e22 实测）

.. code:: text

   7
   10
   5.0
   16.102993301316015

即：\ ``3 + 2 * 2`` 得 ``7``\ （先乘后加），\ ``(3 + 2) * 2`` 得
``10``\ （括号优先）；\ ``(u**2 + v**2) ** 0.5`` 对 ``u=3.0,v=4.0`` 得
``5.0``\ （规范的 3-4-5
勾股风速）；而一旦不加括号写成可误解的形式，就会算出怪数。

**原因**\ ：Python 有一个算术优先级（从高到低）\ ``**`` → 一元负号 →
``* / // %`` → ``+ -`` → 比较 → ``not`` → ``and`` →
``or``\ 。拿不准时程序不会报错，只会\ **按你以为的顺序**\ 做“错事”。正文的忠告是：“**加括号——括号不要钱，可读性值千金。**”

**解决办法**\ ：\ **复杂的表达式一律加括号**\ ，让意图一目了然：

.. code:: python

   speed = (u**2 + v**2) ** 0.5     # 风速 = sqrt(u²+v²)（归一写法）
   temp_in_celsius = (temp_f - 32) * 5 / 9   # 华氏转摄氏
   print(3 + 2 * 2)      # 7
   print((3 + 2) * 2)    # 10

..

   **气象场景一句话**\ ：预报员把写好的公式按自己“心里的括号”读，程序却按“默认优先级”算——多点一对括号，就像公式前后各夹一个台风环流闭合线，圈定范围就再也不歧义。

.. _23-类型转换把字符串翻译成数字:

2.3 类型转换：把字符串“翻译”成数字
----------------------------------

   str → int/float
   是类型转换（\ ``int(...)``\ 、\ ``float(...)``\ ）。转换不是魔法：\ **你给的字符串必须是“数”的样子**\ ，否则抛
   ValueError；而 ``input()`` 天生返回字符串，算数前必须显式转换。

.. _231-intabc--float233x--valueerror字符串不是合法数字:

2.3.1 ``int("abc")`` / ``float("23.3x")`` → ``ValueError``\ （字符串不是合法数字）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

``int("abc")``\ ：

.. code:: text

     File "...\e19_int_abc.py", line 3, in <module>
       print(int("abc"))
             ^^^^^^^^^^
   ValueError: invalid literal for int() with base 10: 'abc'

``float("23.3x")``\ ：

.. code:: text

     File "...\e19b_float_23x.py", line 3, in <module>
       print(float("23.3x"))
             ^^^^^^^^^^^^^^
   ValueError: could not convert string to float: '23.3x'

``int("25.6")``\ （有小数点也不能直接转 int）：

.. code:: text

   ValueError: invalid literal for int() with base 10: '25.6'

**原因**\ ：\ ``int()``
要求参数是\ **纯整数形式的字符串**\ （可带正负号，但不能有小数点、字母、空格等任何杂质）；\ ``float()``
要求是“合法的浮点数字符串”。内容不是，就抛 ``ValueError``\ 。“invalid
literal for int() with base 10” 里的 ``base 10``
表示十进制，“这个十进制的字面量是无效的”。注意这是\ **Value**
Error（类型对、值非法），不是 TypeError。

**解决办法**\ ：先确认字符串长什么样，再选对转换函数：

.. code:: python

   print(int("25"))      # 25         纯整数串 OK
   print(float("12.7"))  # 12.7       浮点串用 float
   print(float("25"))    # 25.0       "25" 也能转 float
   # int("25.6") 不行——要先把"25.6"读成 float 再取整：
   print(int(float("25.6")))   # 25（int() 截断）
   print(round(float("25.6"))) # 26（round() 四舍五入）

..

   正文类型转换清单强调：\ ``float → int``
   是\ **截断**\ 不是四舍五入（\ ``int(25.9)`` 得 ``25``\ ，要四舍五入用
   ``round``\ ）；\ ``str → number`` 随时可能抛
   ValueError，读外部数据（CSV、键盘输入）时最好先用 ``try/except``
   兜底（第 3 章再实践）。

   **气象场景一句话**\ ：想把报文里的站点号串 ``"52889"``
   转成数，结果混进个站名 ``"兰州"``——``int()``
   看到“兰州”写进数字位，瞳孔地震：这个“字面量”根本不是数字，果断 Value
   Error 拒收。

.. _232-input-返回的是-str直接当数字算--typeerror:

2.3.2 ``input()`` 返回的是 str：直接当数字算 → TypeError
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e20 实测，\ ``age = input()`` 后输入
``18``\ ，接着 ``age + 5``\ ）

.. code:: text

   请输入年龄：                                 # 你在键盘敲: 18
     File "...\e20_input_str_add.py", line 4, in <module>
       print(age + 5)
             ~~~~^~~
   TypeError: can only concatenate str (not "int") to str

正确写法（\ ``int(input(...))``\ ，e20b 实测）：

.. code:: text

   请输入年龄：                                 # 输入 18
   23                                            # age+5
   <class 'int'>

**原因**\ ：\ **``input()`` 无论你输入什么，一律返回字符串
``str``**\ 。你以为用户“输入的是数字 18”，Python 拿到的是文本
``'18'``\ 。文本和数字做 ``+``\ ，自然是 2.2.1 同款
``TypeError``\ 。这是大一新课最容易踩的“格式化数据入口坑”。

**解决办法**\ ：凡要参与算术，输入后立刻 ``int(...)`` 或
``float(...)``\ ：

.. code:: python

   age = int(input("请输入年龄："))    # 直接强转成 int
   temp_c = float(input("请输入气温："))  # 天气时要带小数，用 float
   print(age + 5)          # 23（作为数）

若用户可能输入“非数字”，光 ``int()`` 会抛 2.3.1 的
``ValueError``——稳妥做法是 ``try/except``\ （第 3 章讲异常后呼应）。

   **气象场景一句话**\ ：观测员从键盘输入“35”，电脑收到的是文本字符
   ``'3''5'`` 而不是值
   35——保温瓶的旋钮你拧的是“度数”，程序读到的是“刻度编号”。要它当度数，就得先转成数值刻度。

.. _24-变量命名名字要合法能认识:

2.4 变量命名：名字要合法、能认识
--------------------------------

   变量名有四条硬规矩（正文 PEP 8
   摘要）：只能用字母/数字/下划线、\ **不能数字开头**\ 、\ **不能是关键字**\ 、大小写敏感。违反前三者都是
   ``SyntaxError``\ （语法错误）——程序根本不给你跑。

.. _241-变量名用了关键字保留字-syntaxerror-invalid-syntax:

2.4.1 变量名用了关键字（保留字）→ ``SyntaxError: invalid syntax``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e10 实测，\ ``if = 25``\ ）

.. code:: text

     File "...\e10_keyword_var.py", line 3
       if = 25
          ^
   SyntaxError: invalid syntax

35 个关键字包括
``if elif else for while def class return import in is and or not True False None lambda``
等（PPT 第 17 页列了完整清单）。把 ``if``\ 、\ ``for``\ 、\ ``class``
当变量名，Python 会立刻报 ``invalid syntax``\ 。

**原因**\ ：关键字是 Python
的“法定保留词汇”，用于组织语言结构本身，不能被占用为变量名。这就像你不能把自己的名字改叫“并且”“如果”——语法词不能当名词用。

**解决办法**\ ：换一个不与关键字重名的名字（必要时加后缀/加下划线）。

.. code:: python

   if_flag = 25       # ✓ 加后缀避开 if
   for_count = 3      # ✓
   print(if_flag, for_count)

..

   **气象场景一句话**\ ：给探空仪数据文件命名时用了
   ``class``\ 、\ ``for``
   这种保留字，就像在某气旋的编号里塞进“台风”这两个字当普通数字——系统语义立刻冲突，归档接口当场宕机。

.. _242-变量名以数字开头--含非法字符--syntaxerror:

2.4.2 变量名以数字开头 / 含非法字符 → ``SyntaxError``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e11 实测，\ ``1temp = 36.5``\ ）

.. code:: text

     File "...\e11_digit_leading.py", line 3
       1temp = 36.5
       ^
   SyntaxError: invalid decimal literal

``1temp = 36.5`` 报
``invalid decimal literal``\ （“无效的十进制字面量”）。若名字里夹着空格（\ ``my temp = 1``\ ）等其它非法字符，也会报
``invalid syntax``\ 。

**原因**\ ：\ **变量名不能以数字开头**\ （数字开头会被当成“数字字面量”，后面又跟字母，就成了非法的十进制数）。合法的开头是字母或下划线。同时名字里不能有空格、连字符等。

**解决办法**\ ：数字挪到开头以后，或用下划线连接。

.. code:: python

   temp_1 = 36.5       # ✓ 数字放末尾
   temp1 = 36.5        # ✓
   t1 = 36.5           # ✓  但见名知义更好
   today_temp = 36.5   # ✓ 推荐

..

   **气象场景一句话**\ ：给站点文件起名
   ``1station_temperature.txt``\ ，读文件名的那套程序把“1station”当成个非法数字读崩——命名先坐下，数字不许站在最前面。

2.5 容器：list / tuple / set / dict / str 的操作误用
----------------------------------------------------

.. _251-用-listfind--attributeerror-list-object-has-no-attribute-find应-index:

2.5.1 用 ``list.find()`` → ``AttributeError: 'list' object has no attribute 'find'``\ （应 ``.index()``\ ）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e12 实测，\ ``stations.find('敦煌')``\ ）

.. code:: text

     File "...\e12_list_find.py", line 4, in <module>
       idx = stations.find('敦煌')
             ^^^^^^^^^^^^^
   AttributeError: 'list' object has no attribute 'find'

**原因**\ ：\ ``find()``
是\ **字符串**\ 的方法（查子串位置），\ **列表没有**
``find``\ 。你把字符串的习惯套在列表上，Python 翻遍列表的方法表找不到
``find``\ ，抛 ``AttributeError``——“列表对象没有名叫 find
的成员”。这是典型的“对象调错方法”。

**解决办法**\ ：列表找元素用
``.index()``\ （返回第一个匹配的下标）。注意 ``list.index()``
找不到元素会抛 ``ValueError``\ （见下一节对比）。

.. code:: python

   stations = ['兰州', '敦煌', '西宁']
   idx = stations.index('敦煌')   # 1
   print(idx)

..

   **气象场景一句话**\ ：想在站点清单 ``['兰州','敦煌','西宁']``
   里找“敦煌”排第几位，却沿用了文本里 ``find()``
   的老习惯——列表这排“抽屉”根本没有 find 这把钥匙，只有 index
   拼音是对的路。

--------------

.. _252-strfind-找不到返回--1不报错-vs-strindex-找不到抛-valueerror不报错反而更危险:

2.5.2 ``str.find()`` 找不到返回 ``-1``\ （不报错） vs ``str.index()`` 找不到抛 ``ValueError``——“不报错反而更危险”
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

``str.find()`` 找不到子串（e13 实测，查 ``"暴雪"``
不存在的串，程序\ **照常往下跑**\ ，打印出 ``-1``\ ，不报错）：

.. code:: text

   -1
   L

``str.index()`` 找不到子串（e13b 实测，同样查 ``"暴雪"``\ ）：

.. code:: text

     File "...\e13b_str_index_not_found.py", line 4, in <module>
       idx = text.index("暴雪")
             ^^^^^^^^^^^^^^^^^^
   ValueError: substring not found

**原因**\ ：

- ``find()`` 找不到时\ **返回
  ``-1``**\ （设计成“可断言、免抛异常开销”），\ **不报错**\ ；
- ``index()`` 找不到时\ **抛 ``ValueError``**\ 。
  两者的陷阱恰好相反——``find`` 的 ``-1``
  很“安静”，若你紧接着拿它当下标或当“找到了”用，就会算错/取错却不自知（静默污染）；\ ``-1``
  本身不报错，所以你可能根本没注意到。

**解决办法**\ ：根据“子串是否必须存在”二选一，并始终检查返回值：

.. code:: python

   text = "Lanzhou, sunny, 25.6C"
   # 场景A：允许"找不到"，用 find 并主动判 -1
   sub = "暴雪"
   i = text.find(sub)
   if i == -1:
       print("没查到，跳过这块（常见于缺测/字段缺失）")
   else:
       print(f"在第 {i} 位")
   # 场景B：确定必须存在、找不到就该停，用 index（会抛 ValueError 提醒你）
   try:
       print(text.index("暴雪"))
   except ValueError:
       print("暴雪确实不在本观测记录里（业务上就该中断提醒）")

..

   **气象场景一句话**\ ：\ ``find`` 找不到给你一个静默的
   ``-1``\ ，像雷达图上那片“本该有回波却空白”的缺口——不回波、不报警，等你当真没降水去下结论才发现有问题；\ ``index``
   则像缺测站直接打“本站空缺”红标，逼你正视。\ **用哪个要想清楚：能不能接受静默。**

.. _253-用-setappend--attributeerror集合应用-add:

2.5.3 用 ``set.append()`` → ``AttributeError``\ （集合应用 ``.add()``\ ）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e14 实测，\ ``phenomena.append('扬沙')``\ ）

.. code:: text

     File "...\e14_set_append.py", line 4, in <module>
       phenomena.append('扬沙')
       ^^^^^^^^^^^^^^^^
   AttributeError: 'set' object has no attribute 'append'

**原因**\ ：\ ``append()``
是\ **列表/字符串**\ “增加末尾元素”的方法，但\ **集合无序**\ ，没有“末尾”这个概念，所以压根没有
``append``\ 。集合加单个元素用 ``.add()``\ （\ ``set``
也没有下标索引，\ ``s[1]`` 也会报错）。

**解决办法**\ ：

.. code:: python

   phenomena = {'晴', '多云'}
   phenomena.add('扬沙')      # 正确
   phenomena.update(['扬沙', '雷暴'])   # 批量加用 update
   print(phenomena)

运行输出（e14b 实测）：\ ``{'晴', '多云', '扬沙'}``\ 。

   **气象场景一句话**\ ：把“本月出现过的天气现象”存成集合，却想用
   ``append`` 往“队尾”塞——集合是个无序的云滴团，没有队尾可排，只能用
   ``add`` 把新云滴吸进去。

.. _254-列表索引越界--indexerror-list-index-out-of-range含负数空列表:

2.5.4 列表索引越界 → ``IndexError: list index out of range``\ （含负数、空列表）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**

正索引越界（长度 3 却取下标 5）：

.. code:: text

     File "...\e15_index_out_of_range.py", line 4, in <module>
       print(temps[5])
             ~~~~~^^^
   IndexError: list index out of range

负索引越前（\ ``temps[-5]``\ ）：

.. code:: text

       print(temps[-5])
             ~~~~~^^^^
   IndexError: list index out of range

空列表取 ``[0]``\ ：

.. code:: text

       print(temps[0])
             ~~~~~^^^
   IndexError: list index out of range

**原因**\ ：合法下标范围是 ``0 ~ len-1``\ （或负数
``-len ~ -1``\ ）。取下标超出这个范围就是越界，抛
``IndexError: list index out of range``\ 。\ **空列表 ``[]`` 长度是
0，下标从 0 到 -1 哪儿都取不到**\ ，\ ``[0]``
必然越界。常见触发：循环里用死下标、对经过筛选/空化的列表仍按固定下标取、把
``-1`` 当“安全取末尾”却遇到空列表。

**解决办法**\ ：取之前先查长度，或用安全取值方式：

.. code:: python

   temps = [32.6, 34.1, 36.9]
   print(temps[2], temps[-1])     # 36.9 36.9  取最后一个用 -1
   if temps:                      # 先判非空
       print(temps[0])
   else:
       print("序列为空，无元素可取")

..

   结合 2.5.8 记住\ **长度和下标差 1**\ ：长度为 ``len(L)``
   的列表，最大合法正下标是 ``len(L)-1``\ ，最大合法负下标（最后一个）是
   ``-1``\ 。

   **气象场景一句话**\ ：逐日气温列表只有 3 天，程序却要去取“第 6
   天的最高温”——观测还没发生，下标就扑了个空；现实里常因“筛选出空序列”还硬要取
   ``[0]`` 而炸。

.. _255-字典取不存在的键--keyerror:

2.5.5 字典取不存在的键 → ``KeyError``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e16 实测，\ ``station['pressure']``
而字典里没有 ``pressure``\ ）

.. code:: text

     File "...\e16_keyerror.py", line 4, in <module>
       print(station['pressure'])   # 没有 pressure 键
             ~~~~~~~^^^^^^^^^^^^
   KeyError: 'pressure'

**原因**\ ：字典按“键”（key）取值，\ ``station['pressure']`` 要求键
``'pressure'`` 必须存在。键不在，就抛 ``KeyError:'pressure'``\ 。这与
``IndexError`` 同属 ``LookupError`` 家族——``list`` 按下标取爆了是
IndexError，\ ``dict`` 按键取不到是 KeyError，判断方向要分开。

**解决办法**\ ：用 ``.get(键, 缺省值)`` 安全取值，或先 ``in`` 判键。

.. code:: python

   station = {'name': '兰州', 'temp': 35.6}
   print(station.get('pressure', '缺测'))   # 缺测（不报错）
   print(station.get('temp', '缺测'))        # 35.6
   print('pressure' in station)             # False

运行输出（e16b 实测）：\ ``缺测`` ``35.6`` ``False``\ 。

   **气象场景一句话**\ ：档案柜里只有“气温、湿度”两格，你却报“请给我压强的数”——柜子翻不到这格抽屉就嚎出
   KeyError。缺测要素要么先 ``in`` 确认，要么用 ``.get(key, 缺省值)``
   优雅兜底。

.. _256-字符串不可变s0--a--typeerror列表可变可对比:

2.5.6 字符串不可变：\ ``s[0] = 'a'`` → ``TypeError``\ （列表可变，可对比）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e23 实测，\ ``s[0] = "H"``\ ）

.. code:: text

     File "...\e23_str_immutable.py", line 4, in <module>
       s[0] = "H"
       ~^^^
   TypeError: 'str' object does not support item assignment

**原因**\ ：字符串是\ **不可变（immutable）\ 类型，创建后\ 不能原地改**\ 某个字符——``s[0]='H'``
想给索引位置赋值，Python
明确拒绝：\ ``'str' object does not support item assignment``\ （字符串对象不支持“按项赋值”）。而\ **列表可变**\ ，\ ``L[0]='x'``
完全合法（见对照 e23b 实测：\ ``['兰州','敦煌']`` 改
``['兰州新区','敦煌']`` 成功）。

**解决办法**\ ：既然不能就地改，就\ **生成新串**——``s = "H" + s[1:]``
或用 ``.replace()``\ ：

.. code:: python

   s = "Lanzhou"
   s = "H" + s[1:]          # Hanzhou   （保留第1字符后续，替换首字符）
   print(s)
   s2 = "Lanzhou".replace("L", "H")   # 或用 replace

..

   **气象场景一句话**\ ：字符串像镌刻在碑文上的站名，刻错了只能重刻整块碑（生成新串），不能拿凿子只凿其中一个字；列表则像可擦写白板，擦哪个格子都行。

.. _257-切片越界不报错-vs-索引越界报错静默放行-vs-抛错:

2.5.7 切片越界不报错 vs 索引越界报错（静默放行 vs 抛错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ （e24 实测）

.. code:: text

   anzhou        # "Lanzhou"[1:99]：终点远超长度，不报错
                 # ""   （[99:] 空串，不报错）
   [1, 2, 3]     # [1,2,3][0:99] 不报错
   []            # [1,2,3][99:] 空列表，不报错
   IndexError: list index out of range   # 同一列表用 [99] 索引却报错

**原因**\ ：\ **切片 ``[a:b]`` 越界是“静默放行”**——哪怕 ``b``
远超大，Python
也只是“切到能切的地方为止”，返回缩短的结果或空容器，\ **不抛异常**\ 。而\ **索引
``s[99]`` 取单个元素越界会抛
``IndexError``**\ 。这个差异很反直觉：切片让你“想当然”以为没问题，是另一处“不报错更危险”的静默点。

**解决办法**\ ：切片有意取不到就取空时，先想清楚是否该用索引；真正要“限制长度”时，主动用
``min`` 或先 ``len``
判断。能接受空结果就用切片，不能（必须取到）就用索引并配好越界处理。

.. code:: python

   temps = [1, 2, 3]
   print(temps[1:99])   # [2, 3]         安全、静默截断
   # 若要"一定有个元素"，先判非空再取索引
   if temps:
       print(temps[0])

..

   **气象场景一句话**\ ：切片像“取整段天气实况的前 N
   小时”，数据不够就静默返回这么多个小时，不喊疼；而 ``[99]`` 是“非要第
   100 小时的温度”，没有就当场报警。看你想要“宽松截断”还是“严格必取”。

.. _258-len-结果与下标从-0-开始s-1-取末位:

2.5.8 ``len()`` 结果与下标从 0 开始、\ ``s[-1]`` 取末位
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ （e25 实测，\ ``s = "Lanzhou"``\ ）

.. code:: text

   7        # len(s)
   L        # s[0]  第一个字符
   u        # s[6]  下标 = len-1，最后一个
   u        # s[-1] 负索引取末位
   u        # s[len(s)-1]

**原因（不是报错，但常导致 2.5.4 的
IndexError）**\ ：\ ``len(s) == 7``\ ，但合法下标是 ``0..6``——**最末下标
= len - 1**\ 。不差这一格，\ ``s[7]`` 就报 ``IndexError``\ 。\ ``-1``
是取“倒数第 1 个”（末位），\ ``-2`` 取倒数第 2 个……负索引从尾部数、从 -1
开始，正好与正索引 ``0..len-1`` 互补。

**解决办法**\ ：需要“最后一个”时优先写 ``s[-1]``\ ，别写成
``s[len(s)]``\ （必越界）或 ``s[len(s)-1]``\ （也能用但啰嗦）。

.. code:: python

   s = "Lanzhou"
   print(len(s))    # 7
   print(s[-1])     # u   推荐
   print(s[0])      # L   第一个

..

   **气象场景一句话**\ ：序列就像一趟摆好的 7 节车厢，编号却是 0~6（不是
   1~7）——亮 7 节不代表有 7 号车厢可进；“末节车厢”用负号 ``-1``
   从尾巴数最稳，就像从队尾点名报到。

2.6 布尔、None 与判断：真真假假与空值
-------------------------------------

.. _261-none-不是-0直接拿来算--typeerror:

2.6.1 None 不是 0：直接拿来算 → ``TypeError``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e26 实测）

先看布尔：\ ``True`` 在算术里会被当作 ``1``\ ，\ ``False`` 当作
``0``——``True + 1`` 得 ``2``\ ，\ ``True == 1`` 得 ``True``\ （合法）：

.. code:: text

   2
   1
   True

而把 ``None``\ （缺测值）直接拿去加数（e26 最后一行
``precip + 0.5``\ ）：

.. code:: text

     File "...\e26_bool_none.py", line 8, in <module>
       print(precip + 0.5)
             ~~~~~~~^~~~~
   TypeError: unsupported operand type(s) for +: 'NoneType' and 'float'

**原因**\ ：正文强调——``None`` 是独立的 ``NoneType``
类型，表示“\ **这里还没观测**\ ”，\ **不是
0，也不是空串**\ 。\ ``True``/``False`` 作为 ``bool``\ （\ ``int``
的子类）可以参与算术，但 ``None`` 不能当数值。把缺测值 ``None``
直接累加/求平均，就报 ``TypeError``\ 。判空值一律用 ``is None``\ （不用
``==``\ ）。

**解决办法**\ ：把缺测 ``None`` 转成实际占位（如 ``0.0``
或显式跳过）再算：

.. code:: python

   precip = None          # 缺测
   if precip is None:     # 判空用 is，不用 ==
       precip = 0.0       # 业务上"当作没下雨"或跳过该日
   print(precip + 0.5)    # 0.5

..

   **气象场景一句话**\ ：\ ``None``\ （没观测）和
   ``0.0``\ （观测到没下雨）是两码事，把缺测直接塞进求和公式，就像把“今天没测降水”当成“今天降水
   0 毫米”算进月总量——类型先行，先 ``is None`` 判一下。

.. _262-条件里误用单等号if-a--1--syntaxerror应为-:

2.6.2 条件里误用单等号：\ ``if a = 1`` → ``SyntaxError``\ （应为 ``==``\ ）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ （e27 实测）

.. code:: text

     File "...\e27_if_single_equals.py", line 4
       if a = 1:
          ^^^^^
   SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?

Python 3.12 甚至“贴心”提示：你是不是想写 ``==``\ （判断相等）或
``:=``\ （海象赋值）？老版本就只报 ``SyntaxError: invalid syntax``\ 。

**原因**\ ：\ ``=`` 是\ **赋值**\ （把右边值赋给左边变量），\ ``==``
是\ **比较**\ （判断两边是否相等）。\ ``if``
的条件必须是一个“能判断真假的表达式”，而 ``a = 1`` 是一条赋值语句，放进
``if`` 里 Python 直接判语法非法。这是 C 系语言里常见的笔误陷阱（C 里
``if(a=1)`` 还能“侥幸通过”），Python 则从语法层面就\ **禁止在条件里用
``=``** 来保护你。

**解决办法**\ ：写 ``==``\ 。

.. code:: python

   a = 5
   if a == 1:
       print("是1")
   else:
       print("不是1")

运行输出（e27b 实测）：\ ``不是1``\ 。

   记忆法：\ **一个 ``=`` 是“给变量贴标签”（赋值），两个 ``=``
   才是“抽到牌是不是这张”（比大小）**\ 。

..

   **气象场景一句话**\ ：预警系统想判“温度是不是到 35°C”，却写成
   ``if temp = 35``——把“比较”写成了“把 35
   硬塞给温度”，系统直接拒绝承认这是句判断。写预判逻辑时，一个等号和两个等号是一字之差、天壤之别。
