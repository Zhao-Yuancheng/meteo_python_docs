.. _611-整数下标越界--indexerror报错纠正不报错误解:

6.1.1 整数下标越界 → ``IndexError``\ （报错，纠正「不报错」误解）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：很多人误以为「下标超了会静默返回空或
``None``\ 」，\ **恰恰相反——整数下标越界必报 ``IndexError``**\ ：

.. code:: python

   import numpy as np
   arr = np.array([10, 20, 30, 40, 50])
   arr[6]          # 下标最大只能是 4

.. code:: text

   IndexError: index 6 is out of bounds for axis 0 with size 5

**原因**\ ：\ ``arr[6]`` 是「我要第 7 个格点」，数组只有 5 个格点（下标
0–4）。取\ **单个元素**\ 时 NumPy 严格校验下标，越界直接抛异常（axis 0 =
第一根轴，size 5 = 这一根轴上有 5 个元素）。

**解决办法**\ ：先查 ``arr.size / arr.shape``\ ，确认下标
``0 ≤ i < size``\ 。下标从 0 开始——「第 6 个元素」应写 ``arr[5]``\ 。

   **气象场景一句话**\ ：西北 8 站你偏要取 ``temp[8]``\ （第 9
   站），就像夜里点名报到第 9
   号却根本不存在这个人，点名册直接当场叫停——报 ``IndexError``
   正是点名册的「查无此人」。

.. _612-切片越界不报错静默截断空数组与-611-相反的另一面:

6.1.2 切片越界不报错（静默截断/空数组）——与 6.1.1 相反的另一面
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ ：切片的 end 超界\ **不报错**\ ，NumPy
悄悄截断；起点 ≥ size 则返回空数组。这是本章最典型的「一反常态」对照。

.. code:: python

   import numpy as np
   a = np.arange(5)          # [0 1 2 3 4]
   print(a[3:50])            # 末尾越界 -> 静默截断
   print(a[-1])              # 负索引 = 倒数第1
   print(a[5:])              # 起点刚好=size -> 空数组

.. code:: text

   a[3:50]   = [3 4]
   a[-1]     = 4
   a[5:]     = []
   a[2:2]    = [] len = 0     # 空切片

**原因**\ ：整数索引要「精确定位一个格子」，必须合法；切片是「划一块区域」，超出区域的部分自然没有元素，NumPy
选择「宽容截断」而非报错。\ ``end`` 左闭右开、可越界；\ ``start ≥ size``
时得到空切片。

**解决办法**\ ：

- 想要「一定要取到非空」，先 ``if a[5:].size == 0:`` 判断再往下走；
- 别把「切片不报错」误当成「下标不会越界」——**切片宽容，整数下标严格**\ ，两者规则完全不同。
- 负索引 ``-1`` 表示倒数第一个元素，气象里「最后一时刻」常写成
  ``temp[-1]``\ 。

..

   **气象场景一句话**\ ：整数下标像「精确到台站的订正」，报错救命；切片像「截取一段天气形势图」，超出底图的区域就自动留白，安静得很——所以别指望切片帮你报错，要自己
   ``print(shape)`` 盯着。

.. _613-花式索引用浮点非整数下标--indexerror报错:

6.1.3 花式索引用浮点/非整数下标 → ``IndexError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 /
真实报错信息**\ ：花式索引（\ ``arr[[...]]``\ ）只能用\ **整数**\ 或\ **布尔**\ 数组当下标，给浮点数直接报错。注意标量与数组两种写法的报错原文不一样：

.. code:: python

   import numpy as np
   arr = np.array([10, 20, 30, 40, 50])

   arr[np.array([0.0, 2.0])]   # 浮点数组当下标
   arr[0.5]                    # 浮点标量当下标

.. code:: text

   IndexError: arrays used as indices must be of integer (or boolean) type
   IndexError: only integers, slices (`:`), ellipsis (`...`), numpy.newaxis (`None`) and integer or boolean arrays are valid indices

**原因**\ ：下标是「第几个格子」，必然是离散的整数；0.5
号前进括号这种「半个格点」没有意义，NumPy 直接拒绝。

**解决办法**\ ：把浮点下标转成整数再取：\ ``idx = np.array([0.0, 2.0]).astype(int)``\ ；若数据是真的等你取「第
0.0 项」，说明你是想取「第 0 项」，中间多半不需要浮点。

   **气象场景一句话**\ ：你要「取某 3 个时次的样本」，却用
   ``[06.0, 12.0, 18.0]``\ （带 .0 的浮点）去当下标——Offset
   给的是整数，浮点残留十有八九是 ``astype``
   之前把下标算成了小数，先整数化。

.. _614-切片视图-vs-副本改切片原数组也变静默:

6.1.4 切片视图 vs 副本：改切片，原数组也变（静默！）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ ：\ ``base[0:2, :]`` 切片改名 ``sub`` 后，改
``sub`` 里的元素，\ **原数组 ``base`` 也跟着变**\ ，全程无报错。

.. code:: python

   import numpy as np
   base = np.array([[10, 20, 30],
                    [40, 50, 60],
                    [70, 80, 90]])
   sub = base[0:2, :]    # 切片 -> 视图(view)，与原数组共享内存
   sub[0, 0] = -999
   print(base[0, 0])     # 原数组也被改了!

.. code:: text

   改切片后 base[0,0] = -999 (原数组也被改!)

**原因**\ ：NumPy
基础切片返回的是\ **视图**——它只是「原数组上开的一扇窗」，底层数据还是同一份内存。所以「改窗里的景」就是「改窗外的实景」。想独立改动要用
``.copy()``\ ：

.. code:: python

   sub = base[0:2, :].copy()   # 独立拷贝，改 sub 不影响 base

**注意**\ ：\ **布尔索引、花式索引返回的是副本**\ ，与切片正相反：

.. code:: python

   base3 = np.array([10, 20, 30, 40, 50])
   fb = base3[base3 > 20]     # 布尔索引 -> 副本
   fb[0] = -1
   print(base3)               # 仍是 [10 20 30 40 50]，未被改动

.. code:: text

   base3 = [10 20 30 40 50] (未被改动)

..

   **气象场景一句话**\ ：切片 view
   像「把某三天气温网格边界对齐了一帧画布」——你在画布上涂改，那三天的原场也一起脏了；\ ``copy()``
   才是「另洗一份地形图底图」。做完掩码、切片筛选，一律问一句：这
   ``sub`` 是不是会反过来污染源数据？

.. _621-广播形状不兼容--valueerror报错:

6.2.1 广播形状不兼容 → ``ValueError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：两个数组想逐元素运算，但形状对不上号：

.. code:: python

   import numpy as np
   # 西北 8 站 × 5 天气温场
   c = np.ones((8, 5))
   # 逐天订正偏差向量, 本应 5 个(对应5天), 却给成了 4 个
   d = np.array([0.5, 0.2, -0.3, 0.1])
   r = c + d

.. code:: text

   ValueError: operands could not be broadcast together with shapes (8,5) (4,)

**原因**\ ：广播从\ **最右侧（最后一维）往前**\ 对齐，规则是「对应维相等或其一为
1」。\ ``(8,5)`` 与 ``(4,)`` 对齐：\ ``b`` 被补成 ``(1,4)``\ ，最后的
``5`` 和 ``4`` 既不相等、也没有其中一个是 1，直接判死。

逐例看三种典型失败组合（都是实际跑出来的真实报错）：

.. code:: python

   np.ones((3,3)) + np.ones((2,))   # (3,3)+(2,)  最后一维 3 vs 2 不等
   np.ones((3,1)) + np.ones((2,))   # (3,1)+(2,)  末位 1 vs 2 不等
   np.ones((2,3)) + np.ones((2,))   # (2,3)+(2,)  末位 3 vs 2 不等

.. code:: text

   ValueError: operands could not be broadcast together with shapes (3,3) (2,)
   ValueError: operands could not be broadcast together with shapes (3,1) (2,)
   ValueError: operands could not be broadcast together with shapes (2,3) (2,)

**解决办法**\ ：

- 先 ``print(a.shape, b.shape)``\ ，从 ``['尾巴'往前]`` 逐维对照「相等
  or 有一方为 1」；
- 想让 ``(3,1)`` 与 ``(2,)`` 能算了，可用 ``np.broadcast_to`` /
  ``b[:, None]``
  手动把一个维度补成列向量，或直接调整小向量长度，让它对齐到目标维；
- 纯 ``(8,5)`` 与 ``(5,)`` 能直接相加，正是第 6 章正文 6.4
  讲的「把逐天订正偏差加到每一天」的标准写法。

..

   **气象场景一句话**\ ：8 站 × 5 天，订正那 5 天的偏差却只给了 4
   个值——像「对 5 天逐日订正，手里却只有 4
   张效果图」，最后一天不知该对齐到哪，NumPy
   宁可不干也绝不揣摩你心思猜着错。

.. _631-reshape-元素总数不一致--valueerror报错:

6.3.1 reshape 元素总数不一致 → ``ValueError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   import numpy as np
   w = np.arange(6)          # 6 个元素
   w.reshape((4, 2))         # 4x2 = 8 个元素，对不上

.. code:: text

   ValueError: cannot reshape array of size 6 into shape (4,2)

**原因**\ ：\ ``reshape``
不增减数据，只重排形状。目标形状各维乘积（\ ``4×2=8``\ ）必须等于原数组元素总数（\ ``size=6``\ ），否则报错。

**解决办法**\ ：目标形状乘积必须 = ``arr.size``\ 。不确定就留一个 ``-1``
让 NumPy 帮你算（见 6.3.3）。 经典坑：把「8 站 × 5
天」的一维读回平数据想重排成 ``(8,5)``\ ，但还真排元素只有 39 个 =
漏了一站，\ ``print(mat.size)`` 先核对。

   **气象场景一句话**\ ：你录入了 8 站 × 5 天 = 40
   个格点的温度，却想重排成 ``(8,6)``\ （48 格）——多出来的 8
   个格点是凭空捏造，NumPy 拒绝这种「无中生有」的变形。

.. _632-reshape-里写两个--1--valueerror报错:

6.3.2 reshape 里写两个 ``-1`` → ``ValueError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   w = np.arange(6)
   w.reshape((-1, -1, 2))    # 不知道的维度只能留 1 个

.. code:: text

   ValueError: can only specify one unknown dimension

**原因**\ ：\ ``-1`` 表示「这一个维度的大小由 numpy
反推」。若有连续两个维度都用 ``-1``\ ，就有无穷多解，NumPy
无法确定，只能报错。

**解决办法**\ ：只保留\ **一个**
``-1``\ ，其余维度写死。比如「先算有多少行、列数固定为
3」：\ ``w.reshape(-1, 3)``\ ，numPy 会自动推出 2 行。

   **气象场景一句话**\ ：你想要「行数自动、列数 3」的矩阵，却同时告诉
   NumPy「行数和列数都你看着办」——就像经纬度网格只给点数不给分辨率，必然是无穷多个解，报错要求你二选一。

.. _633-reshape-的--1-对应维度除不尽--valueerror报错:

6.3.3 reshape 的 ``-1`` 对应维度除不尽 → ``ValueError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   tiny = np.arange(10)      # 10 个元素
   tiny.reshape((3, -1))     # 3 不能整除 10

.. code:: text

   ValueError: cannot reshape array of size 10 into shape (3,newaxis)

**说明**\ ：这一条在 NumPy 2.x 的报错原文里把 ``-1`` 写成
``newaxis``\ ，不同小版本措辞略有出入，本质都是「\ ``-1``
反推不出来的整数」。 **原因**\ ：\ ``3 × ? = 10``\ ，这个 ``?``
必须是整数，而 ``10/3`` 除不尽，无法给出整数行/列。
**解决办法**\ ：换一个能整除的维度（如
``reshape((2, -1))``\ ），或干脆先 ``print(tiny.size)`` 确认总数。

   **气象场景一句话**\ ：10 天观测想一行 3 天地摆成一列列，最后余 1
   天摆不成矩形阵，就像把 10 天塞进 3
   天一格的行列日历——总会有一天无处安放，NumPy 拒绝「残缺矩形」。

.. _641-nparray-嵌套层级不齐锯齿数组-valueerror报错:

6.4.1 ``np.array`` 嵌套层级不齐（锯齿数组）→ ``ValueError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   import numpy as np
   np.array([[1, 2, 3], [4, 5]])   # 第二行少一个元素

.. code:: text

   ValueError: setting an array element with a sequence. The requested array has an inhomogeneous shape after 1 dimensions. The detected shape was (2,) + inhomogeneous part.

**原因**\ ：NumPy
要的是规整的「矩形」矩阵，每一行元素数必须一致。写成参差不齐（ragged）的嵌套列表，底层无法分配均匀内存，于是报「inhomogeneous（不均匀）shape」。

**解决办法**\ ：

- 逐行补齐到相同长度（短行补 ``nan`` 占位），或用
  ``np.array(..., dtype=object)`` 明确存「对象」；
- 从气象数据源读入时，先 ``pd.read_csv`` 加工成规整表再转
  ``ndarray``\ ，不要手写嵌套列表。

..

   **气象场景一句话**\ ：站点观测表里某一行偏少一个时次，就像和面时某一层少撒了一撮料——整块矩阵就「分层不匀」，NumPy
   拒绝揉一个厚薄不等的面团。

.. _642-数组里混字符串再转数值--valueerror-could-not-convert-string-to-float报错:

6.4.2 数组里混字符串再转数值 → ``ValueError: could not convert string to float``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   import numpy as np
   a = np.array(['15.2', '16.1', 'abc'])   # 温度记录里夹了个非数字
   b = a.astype(float)

.. code:: text

   ValueError: could not convert string to float: np.str_('abc')

同样，读缺测标识文本文件时会遇到（换一下措辞）：

.. code:: python

   import io
   np.loadtxt(io.StringIO("12.5 9999\n13.0 MISSING\n"), delimiter=' ')

.. code:: text

   ValueError: could not convert string 'MISSING' to float64 at row 1, column 2.

**原因**\ ：\ ``astype(float)`` / ``loadtxt``
要求每个字符串都能被解析成数字；\ ``'abc'``\ 、\ ``'MISSING'``
这种缺测标记无法转，直接中断。

**解决办法**\ ：读取时显式把缺测标记转 ``NaN``\ （第 6 章 6.10
的标准做法）——如 ``na_values=["9999", "-999.0"]``\ ，或
``np.loadtxt(..., converters=...)`` 把特定字符串替换成 ``-999``/``nan``
后再转 float。

   **气象场景一句话**\ ：温度记录里被混进一行「MISSING」，就像自动站传回的异常报文——你得先在读取阶段把这些哨兵值认出来转成
   ``NaN``\ （缺测占位），而不是让程序在求和半路上当场噎住。

.. _643-混合类型数组被悄悄字符串化-静默错值静默与-642-相反:

6.4.3 混合类型数组被悄悄「字符串化」→ 静默错值（静默！与 6.4.2 相反）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ ：\ ``np.array([1, 2, 'x', 3.5])``
**不报错**\ ，但整根数组被静默统一成字符串类型：

.. code:: python

   m = np.array([1, 2, 'x', 3.5])
   print(m, "dtype =", m.dtype)

.. code:: text

   m = ['1' '2' 'x' '3.5'] dtype = <U32

**原因**\ ：一个 ``ndarray`` 所有元素必须同类型（第 6 章 6.1
强调的「一个数组只能一种数据类型」）。里面有个字符串，NumPy
只好把\ **全部**\ 元素降级成字符串来装下它——数字也变成
``'1'``\ 、\ ``'3.5'`` 的文本。你后面做 ``m + 1``\ 、\ ``m.mean()``
全都会失败或出错值。

**解决办法**\ ：创建数组前想清楚 dtype
定位；发现数组里混进文本，先定位是哪一行混入了字符串（\ ``'x'``\ ），清洗成数字或
``NaN`` 后再塞回数组。

   **气象场景一句话**\ ：一张本应全是 24
   小时气温的数字表，混进一个抄错的「字」，整张表被迫退化成文本格，气温再也算不动——dtype
   从 ``float64`` 掉成
   ``<U32``\ ，就是这张表「降级成纯文本」的第一信号。

.. _644-字符串数组做数值运算--_ufuncnolooperror--typeerror报错:

6.4.4 字符串数组做数值运算 → ``_UFuncNoLoopError / TypeError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   sa = np.array(['a', 'b'])
   sa + 1                 # 字符串箱 +1 没有对应的底层循环

.. code:: text

   numpy._core._exceptions._UFuncNoLoopError: ufunc 'add' did not contain a loop with signature matching types (dtype('<U1'), dtype('int64')) -> None

**版本说明**\ ：NumPy 2.x 抛 ``_UFuncNoLoopError``\ （如上）；NumPy 1.x
抛的是
``TypeError: ufunc 'add' did not contain a loop with signature matching types ...``\ 。本质一句：\ **\`+’
找不到把字符串和数加起来的底层 C 循环**\ 。

**原因**\ ：\ ``sa`` 里是字符串，\ ``+`` 对 ndarray 执行逐元素的 ufunc
加法，但两个数组里一个 ``<U1``\ （字符串）、一个
``int64``\ （整数），NumPy 找不到「既能算字符串又能算整数」的加法内核。

**解决办法**\ ：先 ``print(sa.dtype)`` 确认有没有被静默字符串化（见
6.4.3）；把非数值元素清洗掉、转成 ``float``/``int`` 后再做四则运算。

   **气象场景一句话**\ ：把站名数组（字符串）和气温数组（数值）直接相加，就像「把『兰州』和
   15.2℃ 加起来」——两个不同语系的观测没法做算术，NumPy
   声明「找不到这种算子的内核」。

.. _645-astype-浮点转整型截断静默丢精度:

6.4.5 ``astype`` 浮点转整型截断（静默丢精度）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ ：\ ``12.7`` 转整型变成
``12``\ ，\ **不报错，也不四舍五入**\ （是直接砍掉小数）：

.. code:: python

   f = np.array([12.7, 13.2, 14.9])
   i = f.astype(np.int64)
   print(i)

.. code:: text

   int 结果 = [12 13 14] (12.7截成12! 不是四舍五入)

**原因**\ ：\ ``astype``
从浮点转整型采用\ **截断（truncation）**\ ，向零取整。12.7 → 12、14.9 →
14。静默，没有任何提示。

**解决办法**\ ：需要四舍五入就先 ``np.floor`` / ``np.rint`` 处理，再
``astype``\ ；气象里若整型只是「站号、时次」，通常无所谓；但若想把「气象温度整型化」去算平均，先想清楚小数位丢不丢得起。

**与 bool 的组合**\ ：\ ``True/False`` 转 int 得到 ``1/0``\ （布尔是 0/1
的“代言人”）：

.. code:: python

   np.array([True, False, True]).astype(np.int64)
   # [1 0 1]

..

   **气象场景一句话**\ ：降水从 12.7mm 记到整型 12mm，一年多满屏站点的
   0.7mm 就全部蒸发——astype
   截断是静默的「小数点收割机」，转换前先问一句精度还够不够用。

.. _646-整数溢出回绕静默错值-int32-vs-int64:

6.4.6 整数溢出回绕（静默错值）→ int32 vs int64
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 /
真实输出**\ ：固定宽度整数超出范围会\ **静默回绕到负数再往上涨**\ ，不报错：

.. code:: python

   x32 = np.array([2147483647], dtype=np.int32)   # int32 最大值
   print(x32 + 1)

.. code:: text

   int32 max +1 = [-2147483648] (回绕为负! 静默)

对比经典例（官方文档）：\ ``100**8`` 在 64 位下正确、在 32
位下严重溢出：

.. code:: python

   np.power(np.int64(100), 8)   # -> 10000000000000000  正确
   np.power(np.int32(100), 8)   # -> 1874919424          溢出, 错误!

.. code:: text

   int64 100**8 = 10000000000000000
   int32 100**8 = 1874919424 (溢出, 错误!)

**原因**\ ：\ ``int32`` 最多表示约 ±21 亿，\ ``100**8=1e16``
远超其上限，位数溢出的位被丢弃，中间结果盘旋回绕。整数运算结果如果可能很大，请用
``int64`` / ``float64``\ ，并留意 Windows 下默认整数类型在某些表达式里是
``int32``\ （Linux 是
``int64``\ ）的平台差异——同一段代码跨机器可能算出不同结果。

**解决办法**\ ：大数运算前先看 ``arr.dtype``\ ；求和计数器、大指数用
``dtype=np.int64`` 或直接 ``float64``\ ；接口与别人不一致时，用
``np.asarray(x, dtype=np.int64)`` 统一。

   **气象场景一句话**\ ：365 天 × 30
   年逐日累计观测、大样本像素统计，一旦用 int32 记账，账本会像计数器冲到
   99 万格就自动清零重来一样，悄无声息算出离谱的负值和错值。

.. _647-忘了-import-numpy-as-np--nameerror报错:

6.4.7 忘了 ``import numpy as np`` → ``NameError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   x = [1, 2, 3]

**原因**\ ：\ ``np`` 只是个别名，是 ``import numpy as np``

**解决办法**\ ：脚本/单元最顶部写

   这位「气象数据处理器」的呼叫代号——没接通呼叫台（没

.. _65-nan-与数值警告多为警告不中断但结果已错:

6.5 NaN 与数值警告（多为「警告、不中断」，但结果已错）
------------------------------------------------------

.. _651-npmean-遇-nan--静默返回-nan静默不对它最阴险:

6.5.1 ``np.mean`` 遇 NaN → 静默返回 NaN（静默！不对，它最阴险）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ ：数组里有 ``NaN`` 时，普通 ``np.mean``
**不报错、不警告**\ ，悄悄返回 ``NaN`` 并传染：

.. code:: python

   import numpy as np
   t = np.array([22.0, np.nan, 28.0, 31.0])
   np.mean(t)     # -> nan  (不打招呼)

.. code:: text

   np.mean  = nan
   np.nanmean = 27.0
   np.std  = nan    np.nanstd = 3.7416573867739413

**原因**\ ：\ ``NaN``\ （缺测占位）就是个「毒数字」，任何算术碰到它结果都被毒成
``NaN``\ 。普通 mean 不自动跳过它。

**解决办法（气象铁律）**\ ：有缺测就用 ``NaN``
安全系列——``np.nanmean``\ 、\ ``np.nanstd``\ 、\ ``np.nansum``
等，它们跳过 NaN 只对真实值求平均，得到
``27.0``\ ；同时统计有效样本数（\ ``np.count_nonzero(~np.isnan(t))``\ ）评估可信度。\ **绝不要
``fillna(0)``**——缺测被填 0 后当真实气温，统计全错。

   **气象场景一句话**\ ：8 站里有一站当天缺测，你用 ``np.mean``
   想算区域均值，结果整片区域均值变成
   ``NaN``——一个坏苹果（缺测站）连累一筐苹果（全部站），这就是气象里「NaN
   污染」；先 ``nanmean`` 才能保住其余 7 站的真实信息。

.. _652-空切片求平均--runtimewarning-mean-of-empty-slice警告不中断:

6.5.2 空切片求平均 → ``RuntimeWarning: Mean of empty slice``\ （警告，不中断）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：对空数组/全 NaN 切片求平均，报一段
``RuntimeWarning``\ ，\ **程序不停**\ ，返回 ``nan``\ ：

.. code:: python

   import warnings
   warnings.simplefilter("always")
   e = np.array([])
   np.mean(e)                     # 空数组求平均
   m = np.array([[np.nan], [np.nan]])
   np.nanmean(m, axis=0)          # 某列全 NaN

.. code:: text

   C:\...\fromnumeric.py:3824: RuntimeWarning: Mean of empty slice
     return _methods._mean(a, axis=axis, dtype=dtype, ...)
   C:\...\_methods.py:142: RuntimeWarning: invalid value encountered in scalar divide
   np.mean(空) = nan
   np.nanmean(全NaN列, axis=0) = [nan]

**原因**\ ：平均值 = 总和 ÷ 个数，分母是 0 无处安放，NumPy 以
``RuntimeWarning`` 提醒你「空切片没有可选的平均值」，然后返回
``nan``\ 。这是「警告(不中断) + 静默 nan」双重标志。

**解决办法**\ ：气象里某站/某日全部缺测是常态，别让 0 个有效样本硬算。先
``np.count_nonzero(~np.isnan(x))`` 看有效数，为 0
就标记该站为「该时段无效」，给 ``nan``
而不是强行塞数字。若确实想屏蔽警告，可
``import warnings; warnings.filterwarnings("ignore", message="Mean of empty slice")``\ ，但\ **更推荐保留警告并处理缺测**\ 。

   **气象场景一句话**\ ：空切片求平均，就像「这天全部站点都罢工没记录」——10
   站里 10 站缺测，你还想求区域均值，NumPy
   只能敲敲警钟告诉你「没有可平均的东西」，返回 ``nan``
   并等你决定这一天的均值该怎么落地。

.. _653-npsqrt负数--runtimewarning-invalid-value返回-nan警告不中断:

6.5.3 ``np.sqrt(负数)`` → ``RuntimeWarning: invalid value``\ ，返回 NaN（警告，不中断）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   import warnings; warnings.simplefilter("always")
   r = np.sqrt(np.array([4.0, -1.0, 9.0]))
   print(r)

.. code:: text

   C:\...\t4_nan_warning.py:20: RuntimeWarning: invalid value encountered in sqrt
     r = np.sqrt(np.array([4.0, -1.0, 9.0]))
   r = [ 2. nan  3.]

**原因**\ ：实数域里负数没有平方根，NumPy 对那个格点返回
``nan``\ （非数字），不影响其余格点，程序照跑。\ ``[4→2, -1→nan, 9→3]``\ 。

**解决办法**\ ：气象里对负数开方常出现在「方差为负（说明前面算了 NaN
或单位错）」或「相对湿度>100」「比湿算错」的格点。求平方根前先：\ ``x = np.where(x < 0, np.nan, x)``
把非法格点标记成缺测，或用 ``np.sqrt(np.maximum(x, 0))`` 钳到 0
再开方。\ **关键是先弄清负数从哪来**\ ，别靠静默垃圾数据蒙混过，尤其当气象变量理论上不该为负（如湿度、分钟降水量）。

   **气象场景一句话**\ ：负值开方在雷达反射率（dBZ
   可以真的为负，但强度不能）这类变量的处理里常冒头——出现
   ``invalid value in sqrt``\ ，先回头查为什么会有负数（多半是缺测没转
   NaN 或差值算反），而不是满足于得到 ``nan``\ 。

6.5.4 ``np.log(0)`` / ``np.log(负数)`` → ``RuntimeWarning``\ ，返回 -inf / NaN（警告，不中断）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   import warnings; warnings.simplefilter("always")

   print(np.log(np.array([1.0, 0.0, -2.0])))

   C:\...\t4_nan_warning.py:26: RuntimeWarning: divide by zero encountered in log

6.6 axis 与多站统计「最佳实践坑」
---------------------------------

.. _661-axis-越界--axiserror报错:

6.6.1 axis 越界 → ``AxisError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：二维数组却指定 ``axis=2``\ （只有 0、1），报
``AxisError``\ ：

.. code:: python

   data = np.array([[12, 14], [18, 20]])
   data.mean(axis=2)

.. code:: text

   numpy.exceptions.AxisError: axis 2 is out of bounds for array of dimension 2

**原因**\ ：\ ``axis`` 越小越靠外。\ ``ndim=2`` 的数组合法 axis 是 0 和
1，\ ``axis=2`` 超过维度范围直接报错。 **解决办法**\ ：记住
``axis ∈ [0, ndim-1]``\ ，或用\ **负 axis**\ ：\ ``axis=-1``
恒指“最后那根轴”，\ ``data.mean(axis=-1)`` 合法且等于
``mean(axis=1)``\ ：

.. code:: python

   data.mean(axis=-1)   # -> [13. 19.]  每行平均

..

   **气象场景一句话**\ ：二维气温场只有「行(时间)、列(站点)」两根轴，你却要
   ``mean(axis=2)`` 沿第 3 根轴压缩——就像问「这张 2 维格点场还有没有第 3
   个空间维」，矩阵本身没有纵深，axis 自然越界。

.. _662-axis-写反形状对数值错--静默错值气象多站最阴险的一坑:

6.6.2 axis 写反：形状对、数值错 → 静默错值（气象多站最阴险的一坑！）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实输出**\ ：对「行=时间、列=站点」的矩阵，把
``axis=0``\ （逐站/按列）错写成
``axis=1``\ （逐日/按行），\ **形状都能算出来**\ ，但含义完全错位、且程序不报任何错：

.. code:: python

   import numpy as np
   # 3 天 × 8 站 气温: 行=时间, 列=站点
   mat = np.array([
       [12,14,16,13,15,18,20,22],
       [14,15,17,12,16,19,21,23],
       [11,13,15,14,14,17,19,20],
   ])
   print(mat.shape)                 # (3, 8)

   per_station_ok          = mat.mean(axis=0)   # 压缩列 -> 每站均值  (8,) 正确
   per_day_wrong           = mat.mean(axis=1)   # 压缩行 -> 每天均值  (3,) 这是写反了还想“每站”

.. code:: text

   正确 每站均值 (8,) = [12.33 14. 16. 13. 15. 18. 20. 21.67]
   写反(实际每天均值) (3,) = [16.25 17.125 15.375]

**关键**\ ：若你的代码里还想「结果的形状恰好一样」，比如矩阵恰好方阵、或你以为结果不保证形状匹配，\ ``axis``
写反经常\ **连形状都看不出来错**——这正是第 6 章 6.10 反复警告的「axis
写反是这类任务最高频的开关错误」。

**原因**\ ：\ ``axis=0`` 沿 ``0``
轴（竖直/行方向）压缩，输出每一列；\ ``axis=1`` 沿 ``1``
轴压缩，输出每一行。多站矩阵约定「行=时间、列=站点」，于是「每站平均」必须是
``axis=0``\ 、「每天均值」是
``axis=1``\ 。写反后你拿着「每天均值」当「每站平均」去画图、去标准化，图像平滑、数值合理、完全不自知。

**解决办法**\ ：

- 动手前先立「矩阵地图」（正文 6.10 的做法）：\ ``print(shape)`` 确认
  ``(时间, 站点)``\ ；
- 用口诀「\ **axis=0 消行输出列、axis=1 消列输出行**\ 」对号入座；
- 逐站统计才做的 Z-score，\ **绝对不能**\ 拿整张矩阵 ``np.mean`` /
  ``np.std()``
  一次算全局——那会抹平站点气候本底差异。逐站标准化应如正文用 pandas
  逐列（天然 ``axis=0`` + ``skipna``\ ），或 ``mat.mean(axis=0)`` /
  ``mat.std(axis=0)`` 得到逐站 μ、σ 后再 ``(mat - μ)/σ``
  沿列广播（行=时间自动广播对齐）。

..

   **气象场景一句话**\ ：一张 8 站 × 10 天气温场，axis
   写反会把「站点」当成「时间」——你本想按站标准化，结果却是按天标准化，整张场标准化后气候本底差异被抹平，而程序照跑、图像照画、结果却完全经不起推敲。这就是
   0.5 节说的最阴险的静默污染：\ **程序绿灯到底，科学结果全错**\ 。

.. _67-布尔掩码与数组拼接:

6.7 布尔掩码与数组拼接
----------------------

.. _671-布尔掩码长度数组长度--indexerror报错:

6.7.1 布尔掩码长度≠数组长度 → ``IndexError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：

.. code:: python

   temp = np.array([22, 25, 28, 31, 33])       # 5 个元素
   bad_mask = np.array([True, False, True])     # 只有 3 个布尔
   temp[bad_mask]

.. code:: text

   IndexError: boolean index did not match indexed array along axis 0; size of axis is 5 but size of corresponding boolean axis is 3

**原因**\ ：布尔掩码必须在每个维度上与目标数组一样长——掩码是「每个格点保留还是丢弃」的开关，一格一个开关，5
个格点配 3 个开关自然对不上。
**解决办法**\ ：掩码要由\ **同长度的数组比较**\ 生成（\ ``temp > 28``
自动得到 5 个布尔），别手写布尔列表；或先
``print(mask.shape, temp.shape)`` 比对。

.. code:: python

   clean = temp[temp > 28]     # 正确, 掩码长度=5+保留极端高温
   print(clean)                # -> [31 33]

..

   **气象场景一句话**\ ：过滤 5 个站的异常高温，却给了一个只标 3
   个站的勾选清单——剩下 2 个站不知道该留下还是划掉，指令自相矛盾，NumPy
   报错让你把开关补齐和站点一样多。

.. _672-npconcatenate-非拼接维不一致--valueerror报错:

6.7.2 ``np.concatenate`` 非拼接维不一致 → ``ValueError``\ （报错）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**现象 / 真实报错信息**\ ：掐
``axis=0``\ （上下堆叠、行数增加）时要求\ **列数一致**\ ，但给了列数不同的两个数组：

.. code:: python

   a = np.zeros((2, 3))
   b = np.ones((2, 5))
   np.concatenate([a, b], axis=0)     # 列数 3 vs 5 不一致, 上下拼接拼接不上

.. code:: text

   ValueError: all the input array dimensions except for the concatenation axis must match exactly, but along dimension 1, the array at index 0 has size 3 and the array at index 1 has size 5

**原因**\ ：拼接只在\ **拼接轴**\ 上增长；其余所有维度必须完全一致，否则接不上。\ ``axis=0``
时只有行数累加，但列数必须相等（3 列和 5 列没法对齐成同一张表的列）。

**解决办法**\ ：

- ``axis=0`` 拼接要求\ **列数相同**\ ；\ ``axis=1``
  要求\ **行数相同**\ ；
- 先 ``print(a.shape, b.shape)``\ ，把两个都 ``reshape`` /
  裁剪到一致的非拼接维。

..

   **气象场景一句话**\ ：把两段不同站点数（3 站 vs 5
   站）的观测尾相接，就像把两段铁轨首尾对接却发现端点错位一个站——第 6
   章正文把那叫「接口尺寸必须严丝合缝」，报错正是指出接口尺寸对不上。

6.8 随机数的可复现性（技巧，非报错）
------------------------------------

.. _681-随机种子nprandomseed-旧式全局态-vs-default_rng-新式局部生成器:

6.8.1 随机种子：\ ``np.random.seed`` 旧式全局态 vs ``default_rng`` 新式局部生成器
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**背景**\ ：气象里「固定随机种子保证结果可复现」（第 6 章 6.10
全文反复强调：\ ``rng = np.random.default_rng(20260817)``\ ）。若不设种子，每次运行得到的“随机”温度都不同，代码看似偶发
bug。两种写法对比如下（真实输出）：

.. code:: python

   import numpy as np

   # 旧式: 全局状态, 影响全程序；同 seed 可复现
   np.random.seed(42)
   print(np.random.randint(0, 100, 5))   # [51 92 14 71 60]
   np.random.seed(42)                    # 重新 seed, 序列复原
   print(np.random.randint(0, 100, 5))   # [51 92 14 71 60]  复现成功

   # 新式: 局部 Generator, 互不干扰, 更推荐
   r  = np.random.default_rng(20260817)
   r2 = np.random.default_rng(20260817)
   print(r.integers(0, 100, 3), r2.integers(0, 100, 3))   # [18 20 66] [18 20 66]

.. code:: text

   seed42 randint : [51 92 14 71 60]
   seed42 再跑    : [51 92 14 71 60]
   default_rng 同seed: [18 20 66]  /  [18 20 66]

**常见坑**\ ：

- 设了 ``seed`` 但别家库（如 tf/sklearn）重新初始化了全局
  RNG，\ ``np.random.*`` 序列就被“抢走”；
- ``np.random.seed(42)``
  是修改\ **全局**\ 随机状态；\ ``default_rng(seed)``
  是\ **局部独立**\ 的生成器，互不干扰——新代码优先用 ``default_rng``\ ；
- 用 ``default_rng``
  时方法名不同：\ ``r.normal(...)``\ 、\ ``r.integers(...)``\ 、\ ``r.choice(...)``\ （而不是旧式的
  ``np.random.randint`` / ``np.random.normal``\ ）。

**解决办法**\ ：气象可复现三部曲——① 脚本最顶
``rng = np.random.default_rng(<固定种子>)``\ ；② 全程只用
``rng.xxx(...)``\ ；③ 换电脑/换 numpy 版本后，用
``rng.bit_generator.state`` 保存/恢复状态，保证跨版本一致性。

   **气象场景一句话**\ ：固定种子就像给模拟实验按下「重演键」——同一场过去
   30 天合成的随机扰动，seed 相同就能原样重放给同学复核；不锁 seed
   的随机场，等于每次重跑都是一场「新天气」，永远无法对照结果。
